# Project lessons

- On 2026-10-23, security verification on Node `24.22.1`/pnpm `11.7.0`/npm `12.2.1` passed the frozen root install, typecheck, build, all 86 tests, real installed DSH CLI/public-host persistence smoke and interface probe. Both root pnpm and independent npm fixture audits reported zero vulnerabilities after patching Vitest/Vite and the fixture's MCP client, fflate and HTTP cache semantics. Keep the fixture's independent overrides: the root pnpm policy does not control npm. Native Node's bundled Undici `7.30.1` rejected all four revoked eMudhra G3b probes (`dv-g3b`, `dv-g3b-aaa`, `dv-g3b-noct`, `dv-g3b-aaa-noct` at `*-emudhra.we-have-a-problem.com`) with `CERT_REVOKED`; the positive `https://example.com` probe returned 200. This repository has no custom CA bundle or container/runtime image to patch; do not disable TLS verification or introduce application CA workarounds. These are local, model-free results, not hosted publishing or notification proof.
- Match the direct Zod dependency to the version used by the published `@deepseek-ai/dsh-session-projection` when implementing its public projection schema contract. During C03, root Zod 4.4.3 produced TS2739 for `stateSchema` against the installed host's public `ZodType` from Zod 4.6.5. The installed host dependency was resolved through the public package using `createRequire`; aligning root Zod to 4.6.5 and running `pnpm install` made typecheck pass. This is an observed declaration compatibility issue, not a claim that every Zod version mismatch fails or that private imports/casts are acceptable workarounds.
- Real host token-meter fixtures must use a balanced step lifecycle: an assistant message without a preceding `step/start` is rejected by the meter. Prefer producing assistant history through the real AgentLoop, or faithfully pair step start/finish events when constructing a fixture; do not weaken host lifecycle or storage checks to accommodate invalid history.
- For isolated command fixtures, mount a concrete `SessionQuery` subclass implementing the public query methods, not the abstract `SessionQuery` service itself. Use the real published query plugin for integration smoke; an abstract service mount is not a working query implementation.
- Respect the published waterfall return contracts: `agent/pre-step` returns `Promise<PreStepDecision>`, while `llm/stream` returns `AsyncIterable`. A stream observer must use an async generator and delegate with `yield* next()`, not an async Promise-returning listener. C07 exercised this public stream boundary to observe durable logs before the actual request; do not invent a `before-step-prepared` host event.
- Original text remains in the host raw log. Shake durable state carries fragment references, source ranges, and checksums, not original-text copies; a reference alone is not recovery authorization.
- Exercise natural-request and cancellation recovery fixtures through the real AgentLoop lifecycle. C07 follow-up diagnosis found that manually appending a turn desynchronized the Agent's phase from session history; balanced event records alone do not reproduce a natural request. Keep public host lifecycle checks enabled and observe the actual follow-up request.
- Completion visibility is not durability: retain current intent through the staged completed flush, then clear and flush; gate a terminal-null completed result before downstream requests too. The chosen replay-safe gate flushes every subsequent natural step while that same-session completed result remains; do not describe it as a process-local durability flag or a one-time retry.
- The published `pruneSession` requires an active natural turn; an idle maintenance callback is not a valid pruning lifecycle. Exercise pruning through the real AgentLoop, and count that real pruning turn's model requests separately from `/shake` command requests. Public `compactNow` owns its maintenance admission; do not wrap it in a second maintenance reservation.
- Public Cordis plugin disposal drains cleanup and reports failures through `ctx.logger.exporter`; `fork.dispose()` resolves rather than rejecting on cleanup durability errors. Assert the exported diagnostics and released resources, not `assert.rejects(dispose())`, and never equate fulfilled disposal with confirmed persistence. C10 exercised both missing save listeners and rejected flush, including one bounded unload durability attempt.
- Inputs queued during maintenance may be consumed individually on subsequent natural turns. Assert that each reaches actual model-request history in order; do not require every queued input in the first request. C10 observed first alone in the first subsequent request, then first/second in the next, with frozen shake selections unchanged.
- Cancel through public `Agent.cancel`, not a forged abort path. An adjacent synchronous prune/replacement pair is atomic; cancellation stops subsequent progress/message submissions and downstream model requests without tearing apart that pair. Retain shared runtime fixtures used by permanent tests; remove only generated bundles and temporary invocation wrappers.
- Public replay adapters resume a new session from script cursor 0. For a reopened pending-shake consumer smoke, provide only the response needed by the next natural request, not the original seed/tool script again. C11 corrected replay observed scheduled/reopen requests 0, natural requests 1, one completed region and exact read page; replay cursor mismatch is a fixture error, not plugin failure. Node package consumption is not an isolated Web-profile acceptance claim.
- Compatibility checks must repin both the root manifest and `.verification/contracts/package.json`: execute/read/recovery/lifecycle tests import the separately resolved published-host fixture. Updating only root dependencies leaves runtime tests on the old host. Exclude nested `node_modules` when copying candidates; use `SHAKE_COMPAT_DSH_VERSION` for the standalone CLI version assertion, and `include-hidden-files: true` when uploading the fixture manifests/lockfiles from `.verification/`.
- Release CI must install `.verification/contracts` with its own `npm ci --prefix .verification/contracts` before the root test suite: execute/read/recovery/lifecycle consume that separately resolved public-host fixture, which root `pnpm install` does not install. Keep npm OIDC publishing in `publish.yml`; only the publish job needs `id-token: write`, and GitHub Release creation runs afterward in a separate `contents: write` job.
- pnpm 11 security settings belong in `pnpm-workspace.yaml`; enforce the requested release-age policy with explicit `minimumReleaseAgeStrict: true`. Verify policy changes against the real CLI using an isolated store/cache: frozen lockfiles are checked too, and the seven-day policy rejected 56 currently pinned entries that had passed the previous one-day policy. The latest-upstream probe intentionally replaces only its temporary workspace config with `minimumReleaseAge: 0`; never copy that exception into the checkout. The independent npm public-host fixture does not inherit pnpm settings, so audit both lockfiles separately without installing dependencies.
- Scheduled workflow incidents follow the compatibility/audit convention: use a separate default-branch reporting job with `always()` and explicit success/failure admission, grant `issues: write` only there, and do not check out or execute dependency code with that token. Find incidents by a workflow-specific body marker among open `github-actions[bot]` issues, paginate the lookup, and exclude pull requests. Dependency audit failures update one incident without repeated comments; only aggregate matrix success closes it. Local smoke verification can execute the actual inline script and condition against a stateful API fixture without creating real GitHub issues; this does not verify notification delivery.
- DSH `0.2.1-rc.2` no longer publishes `dsh-invariants` or any `/invariant` companions; remove their dependencies, imports and registrations rather than pinning an old diagnostic package into the new host. Historical C02–C12 invariant-enabled evidence describes `0.2.0-rc.2`, not the current composition. The new JSONL persistence package exports a plugin namespace (`import * as JsonlPersistence`), not a default class. Its session-projection schema pins Zod `4.4.3`; using root `4.6.5` produced TS2322, and aligning the public dependency restored type compatibility without casts.
- An in-place npm family upgrade can retain old exact peers and fail with ERESOLVE. Resolve the updated fixture manifest in a fresh temporary directory, preserve its independent security overrides, then use the generated lock with `npm ci`; do not use `--force` or `--legacy-peer-deps`. The rc.2 migration passed 93 tests, public-host persistence/interfaces and a built-plugin smoke with zero command requests, one natural request, two reduced regions and exact Unicode reads after JSONL reopen. Current audits are not clean: Zod `<4.6.6` and fixture Undici `8.12.1` are affected by high-severity advisories; npm's propagated package counts are not distinct CVE counts. Keep this risk separate from behavioral compatibility and do not suppress audit failures.
